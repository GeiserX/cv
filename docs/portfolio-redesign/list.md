# Portfolio page, list version

The portfolio page becomes the projects section of my CV at [cv.geiser.cloud](https://cv.geiser.cloud/). It shows my ten public repositories with the most stars. Each row has the repo name linked to GitHub, one line on what it does, the star count as plain text, and a Site link where one exists. No images, no banners, no badges. The rest are one link away on [GitHub](https://github.com/GeiserX). The preview is [list.html](list.html).

Keeping it current is already done for the CV. [`scripts/update_content.py`](../../scripts/update_content.py) computes this exact list every twelve hours from [the update-content workflow](../../.github/workflows/update-content.yml). It skips forks, archived repos and awesome lists, sorts by stars and then by name, and keeps the hand-written one-liners. That sort puts Pumperly before Wayback-Archive, since both have 38 stars. The same GitHub Action could render these rows into the Ghost page and update it through the public Admin API. The site's WAF rejects any request body containing `<img`, `<pre><code` or `<script`, and this page has none of them. The whole body is one html card with its own scoped style, so Ghost's HTML-to-lexical conversion leaves it alone.

Most of today's page goes. An npm tool generates it as 63 cards, each with a centred heading, a banner image and a row of shields.io badges, 206 badges in total, plus a GitHub stats block at the end. The new page keeps ten of those repos and drops everything else, the npm tool included. I would rather have ten rows people read than 63 cards they scroll past.
